# Entity relationship diagram

These are actual mapped domain entities. Identity tables are summarized as ApplicationUser plus its standard Identity role membership; the physical user table is AspNetUsers. Full Identity schema is generated by IdentityDbContext.

Exactly one Appointment provider FK is non-null. Both provider links in the diagram are individually optional but jointly exclusive/required. TrainerClient.ClientId has a unique index in addition to the composite primary key. HealthMeasurement has a unique (ClientId, MeasurementDate) index. Appointment has unique filtered provider/date/time and client/date/time indexes for Status 1/2. Most historical domain FKs restrict deletion; WorkoutExercise deletion clears its optional WorkoutLog reference. User deletion cascades to Notifications and ReminderDeliveries. ReminderDelivery deliberately has no Notification FK.
