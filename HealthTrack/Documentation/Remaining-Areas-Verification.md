# CRUD, PDF, reminder and analytics verification

Scope: continue the existing application without redesign. The working tree already contained extensive prior changes; this audit preserves them. This document records changes made during the 2026-10-08 verification.

## Findings and fixes

- CRUD: exercise deletion cleared historical workout-log exercise references. Exercises now archive, remain available in historical log details, disappear from active plan/dashboard selections, and cannot receive new logs or be edited after archiving. The migration adds `IsArchived` and changes the log foreign key from SET NULL to NO ACTION. Plans with logs still deactivate; accounts with dependencies deactivate; appointments cancel; meal-log data is independent of diet meal templates.
- PDF: direct-download responses already supplied a filename and used the existing PDFsharp/MigraDoc service. A filtered trainer report could omit historical logs after a trainer changed the parent plan dates. Log filtering now uses the log date and authorized plan ownership, independent of current plan schedule. Date, status and client filters are carried into download links.
- Reminders: generation was already wired into authenticated Dashboard, Appointments and Notifications GET flows. Concurrent requests exposed an EF-wrapped SQL deadlock that escaped the existing catch. The handler now checks the exception chain for duplicate/deadlock SQL errors and disposes the entire transaction before returning. It preserves unrelated errors and permits the next page request to retry.
- Analytics: dashboard Active Workout/Diet Plans previously counted future and expired Active-status plans, unlike analytics and client plan previews. Dashboard counts now require today's date to fall within the plan interval in the configured appointment time zone.
- Tests: corrected outdated assertions expecting SetActive links for enabled trainers, included CrudPdf and RemainingCrud in the verification runner, and added history, owner CRUD, SQL analytics and changed-plan-date regressions.

## PDF endpoints

All download URLs append `download=true`.

- `/ReportDownloads/Admin?kind=` System, Users, Clients, Trainers, HealthcareProfessionals, Appointments, WorkoutAnalytics, DietAnalytics, Engagement.
- `/ReportDownloads/Trainer?kind=&clientId=` Progress, Workout, Diet, Appointments.
- `/ReportDownloads/Client?kind=` Progress, Measurements, Workout, Diet, Appointments.
- `/ReportDownloads/Healthcare` own consultations.
- Trainer `/Reports/Progress`, `/Reports/Workout`, `/Reports/Diet`, `/Reports/Appointments` pages link to these downloads with applied filters. `/AdminReports/Print` is an HTML print view, not a PDF response endpoint.

Verification checks attachment Content-Disposition, sanitized dated .pdf filenames, actual browser download events without PDF-preview navigation, PDF parsing/rendering, retained long notes, empty reports, filter inclusion/exclusion and cross-role/ownership denials. The empty workout case makes 20 browser download cases across 19 report variants.

## Reminder and analytics definitions

Reminders are generated on page requests, not by a background scheduler or email delivery. Today reminders apply to upcoming Pending/Approved appointments; tomorrow reminders apply to the next calendar day in the configured time zone. Both participants receive appointment reminders. Daily workout/meal reminders require an Active plan whose dates include today. The `(UserId, ReminderKey)` ledger survives notification deletion; ledger and notification writes commit together. Cancelled/completed appointments are excluded.

Trainer analytics use currently assigned active clients and that trainer's plans/appointments. Admin analytics use system-wide data. Active plans include today. Monthly logs span month start through today. Appointment completion rate is completed divided by all appointments. Popularity groups plan names and counts distinct clients, with recorded log counts shown separately. Most-active clients rank this month's workout plus meal log entries. No static metric values were found.
